# VETO 2.0 — конструктор групповых решений

Не просто голосуй — договорись. Группа задаёт вопрос, собирает варианты и принимает решение по выбранному правилу: **большинство**, **единогласие** или **без возражений**. Итог считает сервер и объясняет, почему решение принято или не принято.

| Слой | Стек |
|---|---|
| Frontend | React 18, TypeScript, Vite, React Router, шрифт Onest (self-hosted) |
| Backend | FastAPI, SQLAlchemy 2, Alembic, PostgreSQL 17 |
| Live-обновления | Server-Sent Events (`/api/rooms/{id}/stream`, `/api/stream`) |
| Наблюдаемость | JSON-логи с `request_id`, Prometheus `/metrics`, Grafana-дашборд, алерты |
| Поставка | Образы backend и frontend, nginx, docker-compose, GitLab CI |

## Быстрый старт

### Локальная разработка
```bash
docker compose -f docker-compose.local.yml up -d postgres   # PostgreSQL на localhost:5432

cd backend && python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements-dev.txt
uvicorn app.main:app --reload --port 8000          # Swagger: http://127.0.0.1:8000/docs
python -m scripts.seed_demo                        # демо-данные (пароль demo1234)

cd frontend && npm install && npm run dev          # http://127.0.0.1:5173, /api проксируется на :8000
```
По умолчанию backend подключается к `postgresql+psycopg://veto:veto-local-password@localhost:5432/veto` (как в `docker-compose.local.yml`). Другую базу задайте через `DATABASE_URL`. Миграции Alembic применяются автоматически при старте.

### Весь стек в Docker (как на сервере)
```bash
docker compose -f docker-compose.local.yml up -d --build   # http://localhost (nginx → frontend + backend)
```
Продакшен деплоит GitLab CI: образы `backend/Dockerfile` и `frontend/Dockerfile`, затем `docker-compose.yml` на VM. Postgres хранит данные в volume `postgres_data`. Фото и ключи push хранятся в volume `backend_data` (`/data`).

Тесты (нужен запущенный Postgres, база `veto_test` создаётся и очищается автоматически): `cd backend && python -m pytest` (40 тестов: Decision Engine, авторизация, права, сценарии комнат, порядок вариантов, ничья и рандомайзер, дедлайн, discovery, фото, поддержка, метрики).

Фото мест (нужен интернет, один раз перед демо): `cd backend && python -m scripts.fetch_photos`. Ключи `PEXELS_API_KEY` / `UNSPLASH_ACCESS_KEY` необязательны — без них фото берутся из Wikimedia Commons.

## Деплой на ВМ (GitLab CI)

Пайплайн `.gitlab-ci.yml`: **test** (40 тестов на PostgreSQL + миграции upgrade → downgrade → upgrade) → **image** (Kaniko собирает `backend` и `frontend`) → **deploy** (`docker compose pull && up -d` на ВМ). Если тесты упали, образы не собираются и деплоя нет.

После деплоя пайплайн проверяет `/api/health`, главную страницу через nginx и что `/api/meta` отдаёт версию именно этого коммита. Если проверка не прошла, в логе пайплайна будут статусы контейнеров и последние строки лога backend.

**Переменные GitLab CI/CD.** Обязательные: `DEPLOY_HOST`, `DEPLOY_USER`, `DEPLOY_KEY` (file), `SPIRIT_DOCKER_SA_KEY` (file), `POSTGRES_USER`, `POSTGRES_PASSWORD` (protected), `POSTGRES_DB`. Необязательные: `PUBLIC_URL`, `COOKIE_SECURE`, `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_FROM`, `SUPPORT_EMAIL`, `PEXELS_API_KEY`, `UNSPLASH_ACCESS_KEY`, `VAPID_SUBJECT` — пустые просто не передаются.

**Данные на ВМ:** volume `postgres_data` (база) и `backend_data` (`/data`: кэш фото и ключ push). Логи контейнеров ротируются (3 × 10 МБ). Демо-данные — ручная кнопка `seed:demo` в пайплайне `master`.

ВМ работает по HTTP: push-уведомления браузеры разрешают только по HTTPS, поэтому они отключаются автоматически. Центр уведомлений внутри VETO работает.

## Что умеет

**Обязательное по кейсу**
- Регистрация, вход, выход, «запомнить меня»; сессия в HttpOnly-cookie, пароли — PBKDF2-SHA256.
- Создание решения: название, вопрос, описание, метод; редактирование настроек до голосования.
- Приглашение по ссылке или 6-символьному коду; вход по ссылке как гость (только имя) с последующим сохранением аккаунта.
- Список участников, выход из комнаты до голосования, удаление участника организатором.
- Варианты: добавление, редактирование и удаление своих до старта; модерация организатором.
- Голосование по трём методам, один набор ответов на участника, автозавершение, когда проголосовали все.
- Результат с объяснением; ничья и несколько приемлемых вариантов показываются как равнозначные, без молчаливого выбора.
- Главная: «Активные» и «Завершённые» решения.

**Дополнительно**
- Шаблоны решений (фильм, ресторан, настолка, поездка, работа, подарок).
- Срок голосования: автозакрытие по поданным голосам и напоминание за час.
- Досрочное завершение организатором (итог по полученным голосам, это видно в результате).
- Ничья 50/50: повторное голосование только между лидерами, возврат к обсуждению или **рандомайзер**. Жребий бросает сервер (`secrets`), один раз, только среди равных лидеров; результат хранится отдельно и **не выдаётся за единогласие**.
- Комментарии к вариантам, скрытие голосов до конца раунда.
- Центр уведомлений и Web Push (Service Worker, VAPID, удаление протухших подписок, разрешение запрашивается только после объяснения пользы).
- «Интересное»: подборка мест, случайное место без уже посещённых и показанных, место дня (стабильно в течение дня), история выбранных мест, сохранённые места. Популярность считается **только из реальных выборов**; пока данных нет, интерфейс честно пишет «Подборка VETO».
- Настройки: профиль, цвет аватара, город, уведомления, тема (светлая/тёмная/системная), смена пароля, удаление аккаунта.
- Помощь: FAQ с поиском и категориями, обращения в поддержку (хранятся в БД, копия на email при настроенном SMTP).

Подробно: [архитектура и релиз](docs/ARCHITECTURE.md) · [сценарий демо](docs/DEMO.md) · API — Swagger на `/docs`.

## Честные ограничения
- Восстановление пароля по email работает только при заданном `SMTP_HOST`. Без него интерфейс не имитирует отправку, а направляет в поддержку.
- Web Push требует HTTPS (или `localhost`) и разрешения браузера; без них работает встроенный центр уведомлений.
- Профили MVP 0.1 (вход по `X-User-ID`) не переносятся автоматически: это была уязвимость. Данные в базе сохранены миграцией.
- Фото подбираются автоматически: Wikimedia (достопримечательности, без ключа), Pexels/Unsplash по ключу (занятия и свои варианты). Wikimedia и Pexels кэшируются на сервере в `/data/photos` (volume `backend_data`); Unsplash по их правилам не перехостится, а подгружается по ссылке. Без интернета показываются обложки категорий.
